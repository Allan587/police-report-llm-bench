# OLBM-48 — Permisos para interacción web de revisores

Consulta pública: 2026-10-30 (America/Costa_Rica); corrección focalizada OLBM-50: 2026-10-30. Estado: `READY_FOR_QA` documental, pendiente de QA independiente. Alcance: ChatGPT Web individual, Gemini Apps Web y Grok en grok.com; las cuentas empresariales, educativas y Grok dentro de X pueden tener condiciones distintas. Esta evaluación no inspeccionó cuentas, sesiones, robots.txt de páginas autenticadas ni contratos institucionales. `UNKNOWN` bloquea la operación automatizada.

**Dos ejes independientes:** disponibilidad funcional = `AVAILABLE_CONDITIONALLY`, `NOT_AVAILABLE` o `NOT_VERIFIED`; autorización concreta del proyecto = `AUTHORIZED`, `NOT_AUTHORIZED` o `UNKNOWN`. Una función anunciada no obtiene autorización por existir. Ninguna operación del proyecto tiene evidencia suficiente para marcarse `AUTHORIZED`; ninguna modalidad está autorizada para información policial real.

## Matriz de decisión

| Proveedor | Automatización web | Función manual (disponibilidad) | Autorización del proyecto | Evidencia | Decisión pendiente |
|---|---|---|---|---|---|
| ChatGPT Web | Extracción programática de Output `NOT_AUTHORIZED` bajo O1; navegación y envío automatizados `UNKNOWN`; también Playwright asistido queda bloqueado | Exportación manual de datos `AVAILABLE_CONDITIONALLY` en cuentas elegibles; copia de respuesta individual `NOT_VERIFIED` como vía de captura controlada | `UNKNOWN` para exportación y transferencia manual; extracción programática `NOT_AUTHORIZED` | O1, O2 | Confirmar plan/cuenta y procedimiento humano; consentimiento institucional para contenido |
| Gemini Apps Web | Playwright `UNKNOWN`, sin autorización demostrada; navegación, envío y lectura automatizados bloqueados | «Export to Docs» `AVAILABLE_CONDITIONALLY` según cuenta y producto; transferencia posterior `NOT_VERIFIED` | `UNKNOWN` para uso web y exportación/transferencia manual | G1, G3–G6; G2 solo histórica | Verificar cuenta, instrucciones legibles por máquina y autorización escrita si se busca Playwright |
| Grok en grok.com | Acceso automatizado sin permiso específico `NOT_AUTHORIZED`; no consta ese permiso, también para Playwright asistido | Exportación privada `NOT_VERIFIED`; enlace público no es vía aceptable para datos del proyecto | `UNKNOWN` para vía manual; automatización sin permiso específico `NOT_AUTHORIZED` | X1–X3 | Solicitar autorización específica de xAI para cualquier acceso automatizado; verificar una vía privada de exportación |

Los estados se aplican a cada operación: navegación, envío, extracción programática y exportación manual son modalidades distintas. Una capacidad técnica, una sesión iniciada, el consentimiento del usuario o la ausencia de prohibición textual específica no constituyen autorización contractual. Tampoco la función de exportar autoriza introducir reportes policiales. La interfaz API oficial es un producto y un contrato distintos: [OpenAI distingue sus APIs de los términos individuales](https://openai.com/policies/row-terms-of-use/), [Google publica condiciones y cuotas propias de Gemini API](https://ai.google.dev/gemini-api/docs/pricing) y [xAI documenta una API con autenticación propia](https://docs.x.ai/developers/rest-api-reference/files). Google describe una capa gratuita variable según modelo y cuenta; esto no autoriza automatizar Gemini Web ni se propone como solución. No se presupone equivalencia de resultados ni permiso transferible a la web.

### Procedencia exigida para una futura importación manual

Una conversación exportada no demuestra por sí misma que se obtuvieron las siete piezas exigidas por `CompleteReviewResult`. Hay dos diseños posibles, ambos **propuestas de implementación futura**:

1. **Opción A — siete respuestas independientes:** siete interacciones distinguibles con el mismo revisor, `statement_index`, run y attempt; cada respuesta debe atribuirse inequívocamente a un slot: `main_review.md`, tres propuestas de historial y tres de perfil para Gemma/Mistral/Llama.
2. **Opción B — una respuesta estructurada:** una respuesta íntegra con siete piezas separables y verificables, que comparten identidad y procedencia.

Ninguna opción es válida hasta definir y probar un contrato de extracción y validación con fixtures locales en un ticket de implementación separado. Ese contrato debe exigir identidad consistente, siete artefactos obligatorios y procedencia verificable; rechazar respuestas parciales y resultados mezclados entre intentos; y prohibir fabricar contenido faltante. Solo los validadores existentes y [`publish_complete_review`](../automation/review/review_storage.py), con manifiesto v2 y referencia activa, pueden publicar un conjunto completo. OLBM-50 no implementa el adaptador ni sus pruebas: importación manual y fixture de procedencia `NOT_RUN`.

Una futura importación asistida tendría que: preparar `main_review.md` y las entradas alineadas con el run antes de transmitir; registrar identidad de cuenta/proveedor/modelo observado, operador, hora, hash de entrada y ruta de procedencia sin credenciales; capturar la respuesta íntegra en un canal privado autorizado; distinguir texto generado de metadatos aportados por operador; validar las siete salidas **del mismo intento**; revalidar O-02 bajo `WorkflowLease`; publicar mediante manifiesto v2/referencia activa; reinspeccionar el set. Una copia manual por sí sola no demuestra origen ni veracidad: sin evidencia suficiente queda `UNVERIFIED` y no cruza la barrera de tres revisores ni la de adjudicación/aplicación. No rellenar campos faltantes, inventar un `run_id` o mezclar intentos. Si el envío o la captura quedan inciertos tras un fallo, detener y reconciliar con intervención humana antes de repetir; la publicación local idempotente no prueba envío externo único.

## Autorizaciones y riesgos pendientes

Antes de **cualquier** interacción real se requieren por separado: (1) permiso contractual del proveedor para cada operación web, cuenta, región y plan; (2) permisos efectivos de la cuenta y sus controles de exportación/retención; (3) autorización del usuario titular; (4) autorización institucional para usar cada servicio y conservar evidencia; (5) base y autorización específicas para transferir información policial, con minimización/anonimización, clasificación, retención y revisión de terceros. Los datos sintéticos no satisfacen el punto 5. La API oficial se evalúa solo como referencia contractual alternativa, sin cambiar la restricción de no usar APIs de pago.

Riesgos concretos: cambios del DOM y sesión vencida pueden truncar capturas; bloqueo de cuenta y límites de uso afectan continuidad; restricciones de automatización impiden un conector aunque funcione; contenido parcial o resultado externo incierto impide reintento ciego; copia sin procedencia verificable no es evidencia suficiente; retención y transferencia a terceros pueden ser incompatibles con datos policiales. Ninguno se mitiga eludiendo CAPTCHA, antibot, cuotas o controles.

1. Confirmar las cuentas, jurisdicciones y términos efectivos; solicitar aclaración escrita al proveedor donde se pretenda Playwright, especialmente xAI y cualquier lectura automatizada. Hasta entonces, deshabilitar envío, lectura y exportación web automática en los tres adaptadores.

3. Elegir y autorizar un procedimiento de captura privada manual verificable para ChatGPT y Gemini; decidir Grok solo tras confirmar exportación privada y procedencia. Registrar quién verifica integridad, no presentar el texto pegado como prueba automática de origen.
